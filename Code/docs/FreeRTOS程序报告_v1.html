    算法图解与麦轮交互演示

    ① 车体速度 → 四轮目标：和 vc_inverse() 对照

    拖动速度滑杆，观察轮组方向、速度和限幅。轮序为 FL、FR、RL、RR；图中前方朝上，横向正方向朝右，wz 正方向采用固件内部逆时针约定。展示的是 vehicle_control.c 的内部输入，不是未经转换的 ROS 消息。示例几何与轮速上限只是演示参数，不能替代车辆标定。

    演示半轴距 L=0.15 m、半轮距 W=0.12 m、ωmax=20 rad/s。仅展示逆解与统一限幅，斜率限制和 PI 在后面的闭环图说明。

    条纹正反转是方向示意，未模拟滚子接地、滑移或实际车速。

    k = L + W，原始轮速：

    ωFL = (vx − vy − k·wz) / r     ωFR = (vx + vy + k·wz) / r
ωRL = (vx + vy − k·wz) / r     ωRR = (vx − vy + k·wz) / r
s = min(1, ωmax / max(|ωi|))     所有轮同时乘 s

    ② 编码器 → 斜率限制 → PI → 输出：闭环结构

    1. 回绕与滤波：Δcount 按 16/32 位模数求差，ωraw=Δcount·2π/(CPR·dt)，α=dt/(τ+dt)，ωfiltered←ωfiltered+α(ωraw−ωfiltered)。
    2. 同步斜率：先求四轮最大目标差，使用同一个 ratio=min(1, αmax·dt/max|ωdesired−ωtarget|) 缩放各轮更新量，避免各轮单独裁剪破坏速度比例。
    3. 换向保护：目标方向改变而实测速度仍高于换向阈值时先输出零；允许改向时也有一个清积分/零输出周期。
    4. PI 与前馈：按目标方向控制幅值；积分是否接受取决于输出是否饱和及误差是否帮助退出饱和。最终再检查实际联锁。

    单轮 PI 的一次计算

    固定 dt=1 ms、Kp=0.1、Ki=0.2、FF=0.02、duty_limit=0.5、旧积分=0；演示方向已建立的稳态分支，不跳过实际固件中的换向保护。

    固件启动：先建立禁止输出，再建立任务

    1. 复位向量经启动汇编复制 .data（包含 .RamFunc）到 SRAM、清零 .bss，进入 HAL 与时钟初始化。
    2. HSE=8 MHz，PLL M/N/P=8/360/2，SYSCLK=180 MHz，APB1=45 MHz，APB2=90 MHz。外设初始化由 Src/main.c 与 MSP 完成。
    3. GPIO、DMA、TIM、ADC、SPI 与 UART 初始化。电机许可及主输出保持关闭；外部急停/禁止线不能由软件绕过。
    4. vehicle_app_init() 启用 DWT、生成 boot_id、初始化授权状态并扫描 Flash A/B 日志。有有效参数才设置 configured；加载不会自动解锁。
    5. 必须擦除时只在启动阶段执行 SRAM 擦除/看门狗服务，绝不在运行任务中擦除扇区；之后创建七个静态任务。
    6. 再启动内部 IWDG，进入调度器。SafetyTask 只有在所监测任务持续推进时才维持正常看门狗服务。

    启动阶段和正常运行阶段的喂狗策略不同。RAM 维护函数仅用于电机被禁止的启动擦除，3 s 超时会停止喂狗；不能把它移入运动任务作为无限续命机制。

    任务 优先级 静态栈（32 位字） 名义节拍 / 触发 职责
    Safety 15 512 2 ms 联锁、急停/故障、授权期限和健康进度；看门狗
    Control 14 1024 TIM6，1 kHz 编码器、PI、输出、健康保护、抖动统计
    HostRx 11 1536 1 ms 轮询 / DMA 接收 Pi/ESP32 双通道解帧、命令与参数
    Imu 10 768 DRDY / 有限等待 SPI 采样、时间戳、姿态输入

    栈值为分配容量，不是测量出的余量。高水位遥测单位同为字，乘 4 才是字节。ISR 处理时间戳、DMA 进度、通知与紧急关闭；高紧急度中断不得直接调用不满足 FreeRTOS 优先级约束的 API。协议、健康和电源核心保持纯 C，应用层负责临界区串行化。

    1 kHz 控制路径与运动安全

    TIM6 → 通知 Control → 时间差/期限检查 → 读 TIM2/3/4/5 编码器
     → 配置版本同步 → 检查运动许可 → 麦轮逆解/限速/斜率限制
     → 编码器差分/轮速滤波 → PI + 前馈/饱和与换向限制
     → 电气健康检查 → 再检查硬件联锁 → DIR / CCR / MOE / ARM

    轮序固定 FL、FR、RL、RR。编码器 16 位计数器按有符号回绕差分处理，32 位计数器使用相应模数；CPR 必须是减速输出轴每圈经正交解码后的有效计数，不能直接填传感器单路脉冲数。

    几何参数包括轮半径、半轴距、半轮距；方向符号和轮安装顺序必须通过单轮测试确认。轮速环不是电流环，采样电流用于诊断与保护，不能据此宣称具备已标定的力矩控制。

    运动许可由已授权来源、租约、指令有效期、无故障、无电源禁止、无 Flash 维护组成；Pi 额外要求 READY。紧急关闭同时撤 ARM、关闭 TIM1 MOE 并清占空比。失联或故障后恢复数据不自动恢复运动。

    正常稳态周期超预算产生控制故障；启动 100 ms 和禁止运动的 Flash 维护窗口不计入正常抖动样本。窗口存在必须在实测报告中注明，不能用被排除的样本证明整车实时性。

    Pi 电源流程与部署闭环

    显式关机请求 → 锁存 power_inhibit → 确认驱动关闭且停轮
→ PC6 请求（A 板转换为 GPIO27 低）→ Linux 有序关机
→ 内核 GPIO22 HALTED → MCU PD1 确认 → PD3 单次切电脉冲

    PowerTask 用实际输出施加时间更新状态机，避免抢占缩短物理脉冲。停止、HALTED 或断电超时只报故障并保留供电，不强行切电，也不自动重复脉冲。重复已接受关机命令可以 ACK，但不重新启动状态机。

    Code/pi/mecanum-bridge.service 当前启动 mecanum_mavlink。配置必须来自同名包，不能使用 legacy 包的参数 namespace。节点启动先将 GPIO17 READY 置低，只有心跳新鲜才拉高；成功关机 ACK 后保持低，退出时释放。两个 ROS 节点不可同时占用串口或 READY。

    GPIO22 必须归内核 gpio-poweroff 所有。发布的 config-halted-pending.txt 是等待真实接线/波形验证的模板，不能把模板存在当作已启用。ROS 停止回调或 Python 不得模拟 HALTED。

    已修复问题

    问题 修复与验证
    启动擦除 Flash 期间可能被外部看门狗复位 不再擦除空白槽；必须擦除时在 .RamFunc 中关中断轮询，每 20 ms 为 PG12 提供 WDI 下降沿，电机 ARM/MOE 保持关闭。3 s 超时停止喂狗等待外部复位；完成后刷新 Flash 缓存。ELF 检查确认函数位于 SRAM 且没有子程序调用；实际擦除波形仍待实测
    参数保存与解锁竞争 同一临界区检查 DISARMED、无待确认授权、配置有效并获取 maintenance。MAVLink / legacy 解锁和运动许可全部受维护联锁约束；编程进行中不能被截止时间提前解锁，完成后保持 20 ms 才释放
    电流阈值与驱动/电机不匹配 根据用户提供的 MG370 单电机约 1 A 堵转电流，采用待标定 1.2 A / 20 ms 过流和 0.8 A / 低速 / 500 ms 堵转阈值，可用宏覆盖；新增约 1 A 输入的堵转测试
    清除计时在滞回带中累计 过流、欠压、过温只在满足恢复条件时连续计时；条件中断即清零。添加“长时间滞回带 + 一次恢复采样不能清故障”测试
    损坏 Flash 头部使后续记录不可见或重写非空槽 固定 84 字节槽逐项扫描，跳过非空损坏记录；只在完全擦除槽追加。测试模型严格执行 Flash 位只能 1→0，覆盖损坏中间头、损坏尾、CRC 回退与满槽轮换
    SBUS 高电平重新授权、缓存样本延长租约 LOW→HIGH 只消费一次；未出现新 LOW 时不能在上锁后自动重解锁。租约以物理帧时间为准，相同时间戳不续租；failsafe 立即撤权。生产默认仍关闭本地运动权，专门以启用宏编译测试
    Pi 默认部署启动 legacy 节点 mecanum-bridge.service 改为启动 mecanum_mavlink；配置也须使用同名包的 YAML，避免协议不匹配
    关机 ACK 丢失后重试被拒绝 对已接受的同一 Pi 关机请求幂等 ACK，不重复触发电源状态机；READY 只在接受 ACK 后因关机而拉低
    无效 ADC 仍可能上报旧 NTC 温度为有效 NTC 有效性必须同时满足 ADC 有效；添加启用 NTC 编译分支测试
    CPU 负载计算无符号下溢与 DWT 频繁回绕 空闲百分比先限幅再相减；DWT 先扩展再转为微秒用于 RTOS 统计。统计计数仍为 32 位，约 71 分钟回绕；跨回绕瞬间的任务统计存在上游内核精度边界，不能作为高精度测量

    参数存储与启动

    程序 Flash 为 768 KiB；扇区 10/11 分别从 0x080C0000 / 0x080E0000 开始，各 128 KiB。每条记录 84 字节：魔数、版本、配置长度、序号、CRC32、boot_id 与 64 字节配置；每扇区容纳 1560 条记录。

    启动扫描最新有效记录，CRC 与参数范围都通过后 configured=1；无有效记录则 configured=0，拒绝解锁。运行期仅 DISARMED 且配置稳定 750 ms 才追加，永不运行期擦扇区；写满下次启动轮换。保存后回读验证，失败通过 cfg_err 诊断；连续编辑时只清除对应版本的 dirty。

    上电和加载有效参数都不会自动解锁。Pi 源仍必须满足真实 READY、电源和 HALTED 联锁；其他来源也必须显式授权并具有新鲜指令与租约。整片擦除会清掉持久化参数，烧录策略必须保留参数区。

    健康保护的真实边界

    • 过流：>1.2 A 持续 20 ms；全部轮 ≤0.6 A 连续 1 s 恢复。阈值来自电机规格输入，未完成电流零点/量程校准。
    • 堵转：有运动许可、占空比绝对值 >0.1、采样电流 >0.8 A、轮速 <1 rad/s 持续 500 ms；条件消失 2 s 恢复。
    • 欠压：按假定 4S 单体 <3.3 V 持续 1 s 触发，>3.5 V 连续 2 s 恢复；电池类型与分压实测须确认。
    • NTC：过温分支支持 75 °C / 1 s 与 60 °C / 2 s 恢复，但默认 VH_NTC_ENABLED=0，现版不能宣称已启用温度保护。
    • ADC 无效持续 1 s 产生传感器故障；有效性恢复不自动恢复运动授权。
    • SOC 只按 4S 电压线性估算，不是 BMS，不测单体、库仑量或均衡。
    • TIM8 ADC 与 TIM1 PWM 同为 20 kHz，但并未硬件锁定采样相位；DMA 当前交接末次扫描，不是每 PWM 周期平均电流。驱动低侧采样在某些占空比/续流状态可能低估实际电流，必须台架验证有效采样窗口，不能仅凭换算公式证明可靠保护。

    FreeRTOS、Pi 与验收

    7 个静态任务：Safety 15、Control 14、HostRx 11、Imu 10、SensorRx 8、Telemetry 7、Power 6。Control 由 TIM6 通知，目标 1 kHz；维护期间硬件输出关闭且不计入常态抖动样本。CPU、最大/最近抖动、7 个任务栈高水位有遥测通路，尚无实测数值。

    MAVLink 关机只允许 Pi 通道、param1=0/param2=2、未运动且 READY 有效；接受后 inhibit，再等待停轮与真正内核 HALTED，最后单次切电。ROS 不伪造 HALTED。Pi 的 config-halted-pending.txt 未作为已验证配置启用；不合并它时，不能指望 Linux 自动提供 HALTED，系统应超时保电并报故障。
